# 整体结构

这类系统里绝大多数混乱，都来自把"**某个东西跑在哪里**"和"**它是什么**"混为一谈。这一页是项目最终收敛出的心智模型的最短版本。

## 两个环境，一个接缝

| | 它是什么 | 它负责 |
| --- | --- | --- |
| **实验环境** | 智能体所在的地方：终端、文件、分析、审批、模型调用 | *判断力* —— 做什么、什么时候、用什么参数 |
| **生产环境** | 世界真正运行的地方：玩家的活客户端、别人的活服务端，或智能体自己拉起来的实例 | 世界本身，以及**只存在于它进程内**的事实 |
| **bridge** | 两者之间的接缝：组合与传输 | 把一堆 I/O 步骤变成**一个工具**，并在两侧搬运数据 |

bridge 不属于实验环境——它是实验环境**用来**够到世界的那个东西。它对你在做什么没有任何意见。

## 一项新能力该放进哪一层？

一个判定，按顺序套：

1. 能不能表达成**原语 + 等待 + 整形**？→ 属于 **bridge**，作为一个组合出来的工具。`mc_command_output` 是标准例子：发一条命令、把它产生的反馈收回来、以数据形式返回。
2. 需不需要**每个 tick**，或者需要**只有游戏进程内才知道**的事实？→ 属于 **mod**。快照是标准例子：实体的 tick 顺序不在存档里，进程外没有任何办法读到它。
3. 是不是**判断**——做什么、什么时候、用什么参数？→ 属于 **智能体**。本仓库里没有任何东西"做决定"。

其余的一切——分析、对比、世界文件的处理、一次性脚本——都属于智能体自己的工具箱（一个终端 + 一个文件系统），本项目刻意不去重造它们。

## 三条轨道，一个 mod

轨道不是三套框架，而是同一个 mod 可以运行的**三种实例**：

| 轨道 | 实例 | bridge 在其中做什么 |
| --- | --- | --- |
| 1 | 玩家的活客户端 | 实时探针与驱动 |
| 2 | 活服务端——也包括单机世界里的集成服务端 | 权威探测、驱动玩家、对真实发生的事作出反应 |
| 3 | 智能体自己供给的实例：无头服务器 + 世界副本 | 供给与运维：装载世界、启动、下命令、冻结、步进、收产物、销毁 |

因为接缝是同一个，为一条轨道写的工具通常也能用在别的轨道上。真用不了的时候，差别通常是**加载了什么**，而不是**能做什么**——实验室里没有玩家，所以没有区块被加载，半径也就没有东西可以量。

## 大脑、手、身体

| | 是什么 | 给你什么 |
| --- | --- | --- |
| **大脑 + 手** | 接口 mod 的服务端 vantage：进程内的代码 | 每 tick 读取与计算、权威数值、以及在同一个 tick 内动手的能力 |
| **身体** | 世界里的一个玩家实体——[Carpet 假人](player-identity.md)或第二个客户端 | "存在感"：踩压力板、被生物仇恨、加载区块、被其他玩家看见 |
| **声音** | 以自己名义发聊天，或者由服务端广播 | 参与对话 |

三者可以只取其一。服务端探针可以通过调用与玩家相同的交互路径去**按按钮**；它做不到的是**存在**——所以任何"只要有个玩家在那儿"就成立的东西，都需要身体。

## 为什么一次分叉需要两样东西

存档不是"一个状态"，而是"一个状态 **+ 它被重建时的顺序**":

| | 由谁记录 | 由谁还原 |
| --- | --- | --- |
| 方块、方块实体、光照 | region 文件 | 拷贝世界 |
| 实体、它们的 NBT，以及**它们的 tick 顺序** | 快照（从活进程里读） | 按记录的顺序 `/summon` |

实体的更新是**逐个计算**的，所以顺序决定了挤压、堆叠、爆炸的结果。快照把顺序记录下来并做了哈希，于是还原可以**被检验**，而不是被相信——这就是 [`fork_verify.py`](fork-verify.md) 做的事，也是"哈希对上了"能作为证据的原因。

## 真正需要写的东西

刻意非常少：

* **mod 里**：只有进程内才知道的东西——tick 顺序、内存态，以及（将来如果它证明了自己的价值）在游戏里跑智能体写的代码；
* **bridge 里**：把多步 I/O 变成一个调用的组合工具；
* **智能体里**：所有需要判断的部分。

技能与配方（怎么拿到世界副本、怎么起实验室、怎么做确定性步进）都是文档，是在**做过一遍之后**写下来的记录——不是框架。

## 刻意不做的东西

* 永远不做用例逻辑：没有大炮代码，没有实验定义。
* 智能体侧不需要常驻守护：智能体可以启动某个东西、等一会儿、之后再回来。
* 在真实需求出现之前，不在游戏里做脚本宿主。实测过的替代方案——全部从进程外做——大约是"看一眼 35 毫秒、一个 tick"，到目前为止所尝试的一切都够用。
* 不做沙箱：智能体写的代码是你自己游戏上的**可信本地代码**。护栏是预算、故障隔离和 kill 开关。

还没有定论的问题都收在 [RFC 提案](rfc/0001-agent-interface.md)里。
